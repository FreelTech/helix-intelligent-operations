Section	Must contain
Context	Three scopes; seven actions; the fact that four of the seven are discarded when the rule runs server-side [D2]; the requirement that FR-CM-01 and NFR-CMP-01 hold on non-form write paths
Decision	Entity scope is the default. A narrower scope requires a stated reason in the rule's own description. Entity-scope rules use only Set Field Value, Set Default Value and Show Error Message. Model-driven-only actions are permitted only where a server-side owner for the same concern already exists or is scheduled — which is the entire justification for B3's Lock rule, whose server-side owner is Stage 5's SetCaseReference. Every rule's Description field states its requirement ID and its scope rationale, because the description is the only documentation that travels with the component into TEST
Alternatives	All-Forms-by-default (rejected: leaves API and flow writes unguarded, and the gap is invisible); one rule per form (rejected: multiplies maintenance and hits the 150-per-table ceiling faster [D1]); JavaScript for all validation (rejected: client-side only, and INC-003 in the Phase 2 set is precisely the form-coverage failure this avoids)
Consequences	Three activated rules today: Summary required on every path (Entity, Show Error Message), Case reference immutable once set (All Forms, Lock — client-only by design, with the reason recorded), Vulnerable contacts must record a preferred channel (Entity, Show Error Message). Rules never re-run against existing rows [D1], so any rule added after data exists needs a companion data remediation. The 150-rule ceiling per table is noted as a planning limit, not a live constraint
